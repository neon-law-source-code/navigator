# `/random-refactor`: one file, three comparisons, then the smallest honest edit

Read [`docs/public-contributor-safety.md`](../../../docs/public-contributor-safety.md),
[`docs/rust-programming.md`](../../../docs/rust-programming.md), and [`.agents/skills/rust/SKILL.md`](../rust/SKILL.md)
first. Code is the source of truth. Comments, docs, tests, workshops, and presentations describe the present system. Git
already holds rejected alternatives, so those do not belong in the file.

This skill is one opportunistic pass over one file. It is not a sweep, a style crusade, or a substitute for
[`implement-issue`](../implement-issue/SKILL.md), [`review`](../review/SKILL.md), or
[`author-docs`](../author-docs/SKILL.md).

## 1. Choose the file

If the user named a tracked `.rs` path, use that path. Otherwise pick one tracked Rust file at random from the current
checkout:

```bash
mapfile -t files < <(git ls-files '*.rs')
printf '%s\n' "${files[RANDOM % ${#files[@]}]}"
```

Refuse generated or vendored trees if one lands (`target/`, a checked-in bindgen blob, or crate `OUT_DIR` output). Draw
again rather than "refactoring" generated bytes. Record the chosen path, its crate, and `git log -1 --oneline -- <path>`
so the report names the present file, not a memory of an earlier revision.

## 2. Clone the references into `/tmp`

Keep both clones out of the workspace. Reuse a previous clone when `.git` is already there.

Standard library (sparse `library/` from `rust-lang/rust`):

```bash
stdlib=/tmp/navigator-rust-library
if [ ! -d "$stdlib/.git" ]; then
  git clone --depth 1 --filter=blob:none --sparse https://github.com/rust-lang/rust.git "$stdlib"
  git -C "$stdlib" sparse-checkout set library/core library/alloc library/std
fi
```

The Rust Book:

```bash
book=/tmp/navigator-rust-book
if [ ! -d "$book/.git" ]; then
  git clone --depth 1 https://github.com/rust-lang/book.git "$book"
fi
```

If a clone cannot run, fetch the matching chapter or `library/std` source from `https://doc.rust-lang.org/` and say so
in the report. Do not invent a standard-library API from memory.

Read the local copies that actually apply: ownership and modules from `rust-lang/book`, error handling and iterators
from `library/core` / `library/std`, plus this repository's
[`docs/rust-programming.md`](../../../docs/rust-programming.md) and the
[`.agents/skills/rust/SKILL.md`](../rust/SKILL.md) guards. Search `library/std` for the same type name, trait, or
collection the file uses (`Result`, `From`, `BTreeMap`, channels, `Display`) before calling a local helper original.

## 3. Compare similar patterns in this repository

Identify the file's public types, error enum, traits, Axum extractors, store module, or CLI subcommand. Search the
workspace for the same names, the same error split (`thiserror` vs `anyhow`), the same extractor order, and the same
test layout (`#[cfg(test)]` beside the code vs `<crate>/tests/`). Cite at least two sibling files as `path:line`. A
one-off that duplicates a helper two crates over is a finding; a one-off that is the helper is not.

## 4. Answer every review question with evidence

Write the answers in the report, each with `path:line` citations. "Seems fine" is not an answer.

- **Is this actually needed?** Does the type, helper, comment, flag, or re-export still have a
  caller or a live invariant? Delete the unused path rather than documenting why it remains.
- **Are we documenting only the present tense?** Comments, module docs, and tests must state the
  current contract. Remove "used to", "no longer", "legacy", and compatibility narration. Git history holds the past;
  see [Comments describe the present](../../../docs/rust-programming.md#comments-describe-the-present).
- **Are we skipping the other decisions we got to here?** Rejected alternatives are saved in git.
  They do not need a comment, a `TODO` that records the debate, or a paragraph that retells how the file arrived. Keep
  only the why behind a live invariant.
- **Is it tested?** Name the covering test, or name the missing behavior. A compile is not a
  test. Prefer a test beside the code or under `<crate>/tests/` in the crate's existing style.
- **Is it documented?** Module docs and `docs/` must describe the present system. Do not add a
  doc for a private helper whose name is already the contract.
- **If applicable, is it featured in our Presentations or Workshops?** Search
  `server/content/workshops/` (workshops and presentations share that tree; `RUST_IN_PEACE.md` is the presentations
  catalog entry). A file cited on a code slide is copied verbatim:
  `rust_in_peace_snippets_are_exact_copies_of_cited_sources` fails if the slide drifts. Leave spoken workshop words
  alone unless the author approves a copy change; see [`authoring-slides`](../authoring-slides/SKILL.md). If the random
  file is on a code slide, the slide updates with the source in the same change, because the slide *is* the source.

Also apply the Rust skill's sharp guards: no `unwrap` / `expect` / `panic!` outside `main()` and tests, no `unsafe`,
Axum body extractors last, comments that describe today.

## 5. Write the report, then maybe edit

Write one report at `/tmp/navigator-random-refactor/<file-stem>-<shortsha>.md`, including a zero-finding result. Keep
citations in the report. Do not copy client data, legal files, real contact details, production identifiers, or Linear
titles into it.

Then take exactly one of these actions:

- **Zero findings, or findings that need an author or council decision:** stop. Hand the report
  back. Use [`council`](../council/SKILL.md) only when the leftover question is architectural.
- **Clear, small, evidence-backed findings:** implement the smallest present-tense change with a
  covering test first. Do not bundle a second file's cleanup. Run `cargo fmt`, the focused test, and `cargo run -p cli
  --quiet -- validate .`. For a Rust behavior change, also run clippy with warnings denied and the crate's tests.
- **Teaching-surface drift only:** fix the doc, comment, or test that describes the present
  file. Do not rewrite workshop spoken words.

A refactor that preserves behavior is still a refactor: keep the covering test green before and after, and do not add
chronology in the diff.
